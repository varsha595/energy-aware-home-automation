# Energy-Aware Multi-Agent Home Automation

An FOAI course project: a simulated smart home where three device "agents"
(a vacuum robot, a washing machine, a dishwasher) share one electricity
budget. A single centralized planner merges their goal requests, plans with
a weighted-A* STRIPS search that is aware of time-of-day electricity
pricing, and dynamically **replans from the current state** (not from
scratch) whenever an action fails, a new goal arrives, or the shared budget
drops mid-execution. Includes a live web dashboard and a scenario-battery
analysis comparing the approach against two weaker baselines.

Read `docs/DESIGN.md` first — it's the STRIPS domain definition (predicates,
actions, preconditions/effects/costs), the heuristic, and the replanning
strategy, written to double as your submission's design section.
`docs/VIVA_NOTES.md` has the defense talking points.

```
│   ├── executor.py         # the execution loop: runs the plan, handles 3 replanning triggers
```

## Setup

```bash
git clone https://github.com/varsha595/energy-aware-home-automation.git
cd energy-aware-home-automation
pip install -r requirements.txt
```

## Run the dashboard

```bash
uvicorn backend.app:app --port 8000 --reload
```

Open http://127.0.0.1:8000. The simulation starts running immediately
(default scenario: Kitchen + Bedroom dirty, one laundry load, dirty dishes,
starting at 09:00 -- inside the peak-price window, so you can watch the
planner defer the expensive wash/dry/dishwasher cycles to 20:00 off-peak in
real time). Use the panel on the right to fire the two replanning triggers
live:

- **Trigger Fault** -- the next action the plan tries to run will fail
  ("device got stuck"), forcing an immediate replan.
- **Add Laundry Load** -- injects a brand-new goal mid-plan.
- **Make a Room Dirty** -- same idea, a second flavor of new-goal trigger.
- **Energy Price Spike** -- shrinks the current window's remaining budget,
  simulating another device switching on unexpectedly.

Watch the Event Log: replans are highlighted amber, failures red, new goals
and price spikes purple, normal actions green -- so a triggered replan is
visually obvious during a demo.

## Run the tests

```bash
python3 -m pytest -q
```

## Run the analysis (generates the report charts/table)

```bash
python3 run_analysis.py
```

This runs a battery of scenarios (quiet morning / typical day / a busy day
with a fault and a new load / a price spike) through three planner
configurations -- the energy-aware planner, a naive planner with no
energy-awareness, and a replan-from-scratch baseline -- each over a few
random seeds, and writes `docs/analysis_results.csv`,
`docs/analysis_summary.md`, and two PNG charts into `docs/`.
